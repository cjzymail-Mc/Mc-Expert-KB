# decision · autopilot-defer-perm-to-human-gate（B 自主流程中途权限命令一律后置人工门）

**决策**：深度授权(B)/全托管的**自主流程中途**，**绝不发起任何会触发用户权限框的命令**（`rm`/删除/无备份覆盖、伸进 `~/.claude`·系统·敏感目录、对外交付）。一律攒进「待人工处理」清单，收尾一次性交用户批量裁决。

**日期**：2026-06-25 入库（源于 2026-06-20 RD48 幻影3.0 deck 深度托管 8h 死锁事故）

**判据轴 = 「是否处于 B 自主流程中途」，不是「用户在不在场」**：
- 执行体无法可靠判断用户此刻在不在；但能确定自己处在 B 自主流程 → 用后者作判据，规则可执行、无歧义（消除「交互式 B」反例）。
- B 模式（无论用户在不在场）中途权限类命令一律后置；**交互式 A 模式 / 普通 `/today` 否档**保留「停下弹框」，不动。

**halt 语义（焊死，防滑向"推翻红线"）**：
- 4 条红线**仍 halt**——红线没消失。改的只是 halt 的**实现机制**：从"隐式靠阻塞式权限框停下"换成「**不执行该命令 + 落盘报告 + halt 上报**」。
- 「后置」= 后置**决策权**给用户，**不是**后置着自己偷偷补做。本该 halt 的销毁性操作仍 halt（不执行+落盘+上报等用户裁决）。一旦"某个本该 halt 的不再 halt"，即从机制细化滑向推翻——这是判别红线。

**理由（事故驱动）**：B 模式中途一条 rm/删除命令给不在场用户弹权限框 → **枯等约 8 小时**，并连带把后台常驻 subagent 一起死锁。不是 fail-fast，是无限挂起。更糟：排查时再跑含 `rm`、伸 `~/.claude` 的 grep → 二次弹框。**B 的对价是"不打扰"，可一旦命令需人工门，阻塞框就把"自动跑"变成"无限等"，比报错更坏。** forensic/排查不例外——别用"会弹框的命令"去查"弹框问题"。

**何时复用此判断**：任何"自主流程中途可能发起需用户确认命令"的链路（team-task B 模式 / `/today` 全托管 / `/free`）。逐项 challenge：这条命令会弹权限框吗？我此刻在自主流程里吗？→ 是则后置人工门，不中途发起。

**与交互式删除纪律的分工**（避免读者困惑谁管谁）：
- **交互式（用户在场手动操作 / A 模式）** → 走 `references/cc-permissions` 第 6 条「含销毁性删除用逐条裸命令、别包脚本、多文件先停下问用户」。
- **B 自主流程中途** → 走本卡「后置人工门 + 落盘上报」。两条互补，不冲突。
