# chop 开工门禁 · 信息充分性自检（chop 产 prompt 前必走）

> chop 的「输入端门」自含资料。从 `通用任务拆解指南`（repo-agnostic 交底协议）+ `批量改造开工门禁`（领域具象）的**原则层**抽取，原封随 skill 保存，**不依赖任何 repo 专属文件**（跨账号 junction 安全）。
> 全文版协议（某些 repo 有）见该 repo 的 `mc-任务拆解指南（必读）/通用任务拆解指南.md`——**软指针，仅供查阅，运行不依赖**（别 repo 没有也照跑）。

---

## 0. 入口分诊（先判任务类型，决定门开多重，别一刀切拷问）

读完原始任务先归一类：

| 任务类型 | 门 | 说明 |
|---|---|---|
| 单点改动 / 从零新建单件 / 纯查询 | **跳重门** | 只跑下面廉价自检；信息齐就直接产精简结构化 prompt，**别拷问** |
| 长链多阶段任务 | **走通用门**（§1–§3） | 信息分三层 + 8 项交底 + 足量性自测 |
| 批量改既有结构化产物（同模板/规则批量改 Office/报告/数据，常伴异构/多版式/历史多层修改） | **通用门 + 批量铁律注入**（§1–§4） | 额外把 §4 避坑铁律 + repo 门禁指针注入产出 prompt |

> "批量"不以件数论，以**是否首次进入某任务类**论。判断犹豫 → 往重里走。

## 1. 信息分三层（决定每条信息归谁、chop 怎么处置）

| 层 | 内容 | 归谁 | chop 的动作 |
|---|---|---|---|
| **可推导层** | 步骤 / 顺序 / 工具选型 / 中间产物 | Claude 执行期 diff 得出 | **不问、不列**——写进 prompt 让执行者实测盘点后自拆 |
| **事实层** | 环境事实 / 业务规则 / 资源边界 | **只有用户知道** | **缺则问**（prose 列清单，见 §3） |
| **裁量层** | 政策偏好 / 风险取舍 / 灰区裁决 | 用户拍板 | **收敛成封闭选择题**列拍板点（AskUserQuestion） |

---

## 2. 八项交底自检（廉价自检，每次都跑）

对原始任务逐项核"在不在场"，缺哪项标为**事实缺口**：

1. **终态**——做完长什么样（描述状态，不描述动作）
2. **参照物**——有没有标准样板（做好的项目 / 模板 / 目标格式）。有参照物时步骤是 diff 出来的副产品，最省字
3. **环境事实**——机器 / 权限 / 加密 / 网络 / 工具链特殊约束（凡"通用经验在此不成立"必写）
4. **业务红线**——不可违反的政策（数量约束 / 命名 / 不可改原件 / 合规）
5. **资源边界**——什么已丢失 / 不可再生 / 缺口由谁补（补料 vs 近似替代 vs 接受残缺）
6. **验收标准**——写**结果属性**（"内容自洽""与源 1:1 对账"），每条"最后会挑的毛病"都写进去（会自动逼出隐藏步骤）
7. **裁决偏好**——保守 / 激进；AI 替代·推断件要不要显式标记；拿不准停还是按默认走
8. **干预带宽**——几轮 plan 评审 / 多久回拍板点 / 里程碑粒度

**足量性自测**：把这份任务想象成发给一个**零上下文新会话**——若它第一个问题是你本可预料的事实（"数据在哪""有没有样板"），说明交底不足，补进去再产 prompt。

## 3. 问 vs 列拍板点（边界，别问错、也别拷问轻任务）

- **问（事实层，且执行期 inspect 也得不到）**：用**一条 prose 消息列缺口清单**请用户补。**开放事实不要塞 AskUserQuestion**（它模态 / ≤4 选项，只配封闭题）。只问"用户独有、inspect 不可得"的事实。
- **不问、留执行期**：可 inspect 的（现状 / 模板异构 / 文件清单）→ 写进 prompt 让执行期盘点，chop 不问。
- **列拍板点（裁量层）**：收敛成封闭选择题（P1: A/B + 默认建议），用 AskUserQuestion。
- **既不问也不列**：可推导层 → 写进 prompt 让执行者自拆。
- **防双重拷问**：执行期还会"盘点先行 + 追问义务"再过一遍——chop 只接事实层用户独有项，别和执行期重叠。
- **team-task 被调用模式**：重缺口可落 `team-progress/questionnaire-<run_id>.md`（schema 见 `../team-task/funnel-gate.md`）；没有墙钟超时，FACT 不默认，只有用户填答或显式 `continue-defaults` 才回收，其中默认仅适用于带安全默认的 PREFERENCE。防双重拷问边界不变。

---

## 4. 批量改既有结构化产物 · 避坑铁律（仅原则；具体形状留 repo 门禁 skill）

识别为该类任务时，把下面**原则**注入产出 prompt 的【事实交底】/【你的任务】。**不要**在 chop 里复刻四阶段 / 5 要素机器——那是 repo「批量改造开工门禁」类 skill 的活，且其自标"草案 v0、仅工艺单验证、具体形状待跨类校准"，烤进全局 chop = 过拟合。

- **放量前必有一道输入端门**（避坑铁律）：探测取证先于讨论；**禁抽样**发现异构（对全量做廉价只读结构指纹、聚类成版式族）；盘清历史多层修改；plan 批准前不动手。
- **条件指针**：本 repo 若配「批量改造开工门禁」类 skill → 在 prompt 写明"放量前走之（探测 → 5 要素 spec → 用户签字落 plan）"。
- **降级（repo 无门禁 skill）**：仍把上述铁律的**实质**写进 prompt（探测先行 / 禁抽样 / 盘历史层 / 首件验收逐级放量），只是少一个 forcing-function 文件，**不报错、不空等**。
- 输入端门与执行端门（dry-run / 自检 / 人审）**互补不取代**。
