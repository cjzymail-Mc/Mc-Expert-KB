## 参考信息：如何将复杂任务从【人工拆解】转向【自动拆解】？？

从【人工拆解】转向【自动拆解】
 - 给终态和参照物，不给步骤，让 claude 自己拆
 - 补充全局重要信息（全解密可走 py、文件丢失+硬凑、强制 3 轮）
 - 第一个里程碑定为一份完整的拆解计划，先验收该计划
 - 要求 Claude 把无法决策的疑点列成拍板点
 - 每个阶段建议施工方式：team / subagent / 单干
  （如果单干，关键验收环节：例如首次生成的 plan 文件，务必让 mc-expert 带验收背景信息把关）
 - 明确 plan 的几个重要验收里程碑
 - 验收遵循「首件验收」（first article inspection）模式：在最便宜的环节拦住系统性错误，再放量

## Fable 示范 【自动拆解】 prompt

【终态】RD48-58 每个项目补成 RD38 标准项目的完整度（8 子目录、文件齐全、命名自洽）。
【事实交底】
    ① 系统原始文件已丢失，缺口只能从现存文件近似替代；
    ② 业务规则：每款 3 轮打样；
    ③ 文件已全部预解密，遇密文记清单停下。
【你的任务】先不动手：盘点现状 → 对照 RD38 拆出阶段和步骤 → 每步写明判定规则 → 你定不了的列成拍板点问我。我批准 plan 后你再执行，按里程碑交付。
【验收】 验收遵循「首件验收」（first article inspection）模式：
  ① 素材映射表（纯文本先验）→
  ② 1 份 html（指定素材匹配度最差的项目做首件）→
  ③ 同项目 1 份 ppt（只验渲染层）→
  ④ 第 1 个项目整体自洽 →
  ⑤ 剩余 2 项目批量 + 抽检红线项。

## 改写后的【自动拆解】prompt（2026-06-12）—— 完整范例

【终态】RD48/RD50/RD51 三个项目的【8-竞品对比报告】ppt 内容完整、数据详实、图文并茂，完整度对齐 RD38 标准项目的同名报告。

【事实交底】
    ① 现有三份 ppt 是此前凭空生成的，内容单薄，不可作为数据真相，只可作为骨架起点；
    ② 原始素材在 `D:\Technique Support\Claude Code Learning\[Agent-4 Claude] Wu Prj\【补充-竞品对比报告】`，内容丰富但不完全匹配 RD48/RD50/RD51；素材已全部备份，图片、chart、文本框、文字、日期均可任意复用、修改、删除；
    ③ 该文件夹已是系统中能找到的全部资料，系统原始文件已丢失——缺口只能通过修改素材近似替代 + 生成新内容填补，不存在"再找资料"选项；
    ④ 业务规则：每款 3 轮打样；
    ⑤ 文件已全部预解密（可走 python 提速），遇密文记清单停下。

【红线】全部环节产物（md / html / ppt）禁止出现【替代】【推断】这类字眼。

【你的任务】先不动手：盘点现状（三份现有 ppt vs RD38 标准报告 vs 素材库三方对照）→ 拆出阶段和步骤 → 每步写明判定规则 → 每个阶段建议施工方式（team / subagent / 单干）→ 你定不了的列成拍板点问我。第一个里程碑就是这份完整拆解计划，我先验收 plan，批准后你再执行，按里程碑交付。

【验收】按首件验收、逐级放量的阶梯走，每级只验该级新增的失败模式，过了上一级不重复审：
    ① 素材映射表：哪份素材喂给哪个项目哪一页、改哪些身份信息，纯文本对照表先验；
    ② 1 份 html（选素材匹配度最差的项目做首件）：数据自洽、3 轮打样规则体现、红线字眼为零、身份信息清洗干净（源项目名、源日期、源款号一律换成目标项目信息）；
    ③ 同项目的 1 份 ppt：只验渲染层——排版、图片/chart 复用效果、完整度对齐 RD38，内容不重审；
    ④ 第 1 个项目整体：项目内多份产物之间日期、款号、轮次互不打架；
    ⑤ 剩余 2 个项目按同套判定规则批量跑，我只抽检红线项（字眼、身份信息）。
