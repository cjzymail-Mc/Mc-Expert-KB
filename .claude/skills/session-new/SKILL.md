# session-new

我准备清空当前 session、重开一个新会话。在关闭前，把当前讨论固化成**新会话冷启动可自足接续**的交接物，防止上下文丢失。按下面四步执行，最后给我汇报。

> 核心分工：**session 专属的交接内容进 plan（一次性、不进 memory）；memory 只收真正跨会话复用的反射/偏好**。别把一次性讨论塞进 memory 污染索引。

## 第 1 步：把当前讨论固化成 plan md（必做）

**1a 定存放位置 + 命名（按优先级自适应，命中即停）：**

1. 当前 repo **有明确的 plan 文件夹**（如 `mc-plan/`、`plans/`、`plan/`、`.claude/plans/`）→ 存进去，**沿用该文件夹既有命名规范**（如 `sub-plan-NN-xxx.md`、`main-plan.md`；有序号的取最大 +1）。
2. 否则**上下文/根目录已有 plan 文件**（`plan*.md` / `plan-*.md`）→ **沿用其命名风格 + 同一存放路径**（如根目录 `plan-<主题>.md`）。
3. 都没有 → **默认存当前项目根目录**，命名 `plan-<主题-kebab>.md`。

> 先 `Glob` 探一眼（`mc-plan/`、`plans/`、根 `plan*.md`）再决定，别凭感觉。落位有疑义时按上面优先级走，仅在多个候选冲突时才问我。

**1b plan 内容要求（冷启动自足）——新会话没有本次对话历史，靠这份 + 文中引用的事实源就能接上：**

- **目标**：一句话说清要做什么。
- **执行环境**：目标 repo 绝对路径（**注意区分"plan 存放 repo"与"执行 repo"，二者可能不同，写清**）、开工必读文件。
- **关键决策（已拍板）**：本次讨论已经定下的方向 + **为什么**（尤其是排除掉的方案，防止新会话走回头路）。
- **前提状态**：已达成的前提 + 快速核验方式。
- **实施步骤**：可执行清单。
- **待拍板决策点**：尚未定的，**带建议默认**（让新会话能带默认推进，仅出问题时回头问）。
- **边界 / 红线 / 不要做**。
- **成功标准**。

## 第 2 步：更新 memory（走 mc-update 纪律，从严）

**不是必更**。session 连续性主要靠 plan，不靠 memory。仅当出现「**1 年内会被反复需要 ≥3 次的跨会话反射/偏好/元规则**」才考虑，且：

1. **频次闸**：≥3 次才继续，一次性讨论不写。
2. **去重闸**：先 grep `.claude/{auto-memory,memory}/` 或 harness memory 目录，同主题已有 → append，没有 → 才新建。
3. **归属**：用户偏好/跨主题元规则/高频反射 → auto-memory；特定任务/技术细节/一次性踩坑 → memory。本次若有「**对我工作方式的纠偏**」（如否决某方案、换路线），优先按 feedback 存并写明 **Why + How to apply**。
4. 写完同步更新对应 `MEMORY.md` 索引。

## 第 3 步：固化必须的状态文件（按 repo 既有约定）

仅更新「不写新会话就会丢」的状态载体，**沿用 repo 既有约定**，不新造：

- 有 `STATE.md` → 若本次产生结构性变更/里程碑，按其格式 +1 行（参照 `/mc-update` 的结构性变更判据）。
- 有 `team-progress.md` / 进度载体 → 更新「当前现状 / 下一步 / 卡点」。
- 有 `todays-task.md` 类入口 → 若下次要接着干，留一行指向 plan。
- 新增了 slash command / 顶级目录等结构性变更 → 按 `/mc-update` 第 3 步 4b–4e 同步 CLAUDE.md / STATE.md。

> 拿不准某文件要不要动，就**不动**——宁可在汇报里提示「建议手动确认 X」，也别擅自改状态文件。

## 第 4 步：汇报（必做）

给我两样：

1. **plan 存放路径**（绝对路径）+ 为什么存这（命中了 1a 哪条规则）。
2. **更新文件明细**：逐条列「文件路径 — 改了什么」。包括 memory（含新建/append/未动及原因）、状态文件、索引文件。没动的大类也说明「未动 + 原因」，让我一眼看全。

## 反例

- ❌ 把一次性讨论内容塞进 memory（应进 plan）。
- ❌ plan 写得依赖本次对话历史（新会话读不到，等于没写）。
- ❌ 没探测就默认存根目录（repo 有 `mc-plan/` 却没用）。
- ❌ 擅自改 STATE.md/team-progress 等状态文件却没在汇报里说明。
- ❌ 汇报只说"已更新若干文件"不给明细路径。
