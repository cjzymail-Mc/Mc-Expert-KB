# task-decomposition.md — 长链任务交底协议（跨 repo 通用）

> KB 事实手册 / 可复用 playbook。源：Agent-4 Wu Prj `mc-任务拆解指南（必读）/通用任务拆解指南.md`（2026-06-10，用户刻意抽象成不含项目专名、可搬任何 repo）。
> 本卡只蒸馏**核心模型**；8 项交底清单全文 + 布置模板 + 反模式表见源文件，按需 `--add-dir` 读。
> 解决的问题：长链任务里用户被迫当"人工拆解者"，每步喂任务、每细节都盯。

## 核心模型：信息三层，只有一层必须用户提供

| 层 | 内容 | 归谁 |
|---|---|---|
| **可推导层** | 步骤 / 顺序 / 工具选型 / 中间产物 | **Claude**（给终态+参照物即可 diff 出来） |
| **事实层** | 环境事实 / 业务红线 / 资源边界 | **只有用户知道，必须交底**——拆解错误的头号根源 |
| **裁量层** | 政策偏好 / 风险取舍 / 灰区裁决 | 用户拍板，但 **Claude 负责把问题识别出来并收敛成封闭选择题** |

> 用户写步骤 = 用自己的时间做 Claude 能做的事，还把合同锁死在单步上。用户精力应全花在**事实层（交底）+ 裁量层（答题）**。

## 两段合同：拆解与执行分离

- **第一段（拆解合同）**：交付物 = plan 文档 + 拍板点清单。**plan 批准前不许动手**——错误假设留纸面成本最低，落盘成产物就是返工。
- **第二段（执行合同）**：按批准 plan 跑、里程碑交付；途中灰区**不停机**记入待裁决队列凑批问；同方案连失 2 次熔断（不原地重试）。

## Claude 侧三义务（写进协议，不靠自觉）

1. **盘点先行**：拆解前必须实测（派 Explorer 并行），不许引用记忆里的"上次好像是"。
2. **追问义务**：拆解前先列"我还需要确认哪些事实/规则"，而不是拆错后被纠。
3. **拍板点封闭化**：给「P1: A/B + 默认建议」封闭选择题，不给开放题"你觉得呢"。

## 一条铁律：纠输入不纠输出

纠错时纠**事实/规则假设**（"你假设数据能找回是错的，实际已丢失"→ Claude 自己重排全链），**不纠步骤**（"第 3 步改成 X"→ 下次它还等你指挥，你又回到拆解者角色）。

## 两个诚实限制

- 拆解必有错漏（冷启动凭描述想象现状时尤甚）→ 防线就两道：**盘点先行 + 用户审 plan 那一轮**，都省则错误假设一路跑到产物。
- "少量干涉"≠ 零干预。用户最小出场：开工交底（10-20 行）→ 审 plan（1 轮）→ 答拍板点 → 验收里程碑。低于此质量不保。

## 与既有反射的关系

本协议把现有件串成**任务入口**打法，不重复造：盘点先行=[[../reflexes]] inspect-first；连失 2 次熔断=[[../reflexes]]；收尾固化=[[../decisions/kb-memory-boundary]] 沉淀分两轨；执行编排权=[[../decisions/orchestrator-route]]。新增维度 = 信息三层模型 + 交底清单 + 纠输入不纠输出。批量产线的验收排程另见 [[acceptance-ladder]]。
