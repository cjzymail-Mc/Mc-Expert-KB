# 会话交接与流程分发判断库

先确认接手者下一步要做什么。新会话或另一个 agent 接续当前任务时，查中断位置、下一步和交付物。交给同事复跑或维护时，查对方能拿到的材料、目标环境和首个可核对的业务结果。

## 已明确的要求

历史取舍保留各自的任务条件、接收者和使用场景。用户明确要求跨任务沿用的做法在此登记。

## 新会话或另一位 agent 接续任务

沿真实任务追踪谁持有下一步、从哪里恢复、交付物在哪里，以及由谁核对。区分流程执行到位与产物达到要求。优先修正在真实失败时让工作中断的那一步，保留已经验证过的结果。正式工程陪审仍走 mc-expert 的既有合同。

- 恢复方案至少覆盖当前遇到的失败位置。若中断位置不确定，就以任务中途丢失会话验证继续入口，并与正常交接作对照。交棒后若对端无动作，追到接棒方的消费记录，核对唤醒是否错过及原协议能否幂等重发。 见 [H01](cases.md#h01)。
- 把执行流程与交付结果分开核实。复用既有结论前确认所指版本和范围，随后复核新增或受影响部分。 见 [H02](cases.md#h02)。
- 交接页应让新会话找到当前目标、最后可靠产物和下一步。接续摘要中提及的已完成改动，核对相应文件或运行记录后再用于决策。旧约束的诱因消失后，查清依赖并修准原条，减少互相冲突的历史要求。 见 [H03](cases.md#h03)。

- 复盘指定的一次团队运行，用其任务书、启动记录和验收条目对齐起止范围，再分别核算新增业务证据、交接等待和返工。可延后的人工决定归入约定的审核点；若决定阻断当前工作，说明具体依赖。见 [H04](cases.md#h04)。

## 同事取得流程后复跑或维护

- **先确定接手者要完成的第一项工作。** 若同事拿到同构项目副本，只需重做同类业务，优先交代稳定的资料类型、目录约定、查找方法及调用顺序，用一个成品实例说明验收。处理文件名等项目差异时保留接手者的选择空间。见 [D01](cases.md#d01)。
- **以接收方拥有的东西界定包的自足程度。** 为不同机器分发时，列出随包业务文件、可按固定来源重建的依赖、需在目标机建立的本地设置。与项目共用的文件注明从包内或约定仓库如何取得。授权登录由接收方在其目标环境完成。见 [D02](cases.md#d02)。
- **业务逻辑和调用方式分别处理。** 先找出一次真实任务的输入、输出及已有实现。多端共用时，能复用的解析、计算和校验保留在同一份业务代码中，入口差异放到各自适配层。是否追加服务接口，取决于将由谁调用、多少团队维护，以及输入输出是否已稳定。见 [D03](cases.md#d03)。
- **冷启动验收从收包后的入口起步。** 用接手者可获得的包和样本，在接收环境或标明边界的干净环境，跑到第一次可核对的业务结果。核对文档所写命令、缺少的依赖和需要本机提供的输入。清点了文件、在开发机运行过、另一位操作者已成功运行，三种证据分别记录。见 [D01](cases.md#d01) [D02](cases.md#d02)。
