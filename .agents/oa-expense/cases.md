# OA 报销与业务单据协作案例

<a id="e01"></a>

## E01 用历史单据建立新的草稿

用户描述了重复工作的入口：指明某张历史单据作为模板，另行提供当次的发票和费用统计表，要求新建、填写和保存，停在草稿。随后补充，办公室中其他同事也会操作。可复用的经验是先辨认业务类型与字段，再用当次材料确定申请主体和金额，保存后核对草稿及明细。这里记录的是用户定义的操作边界，不能据此认定某一张单据已经保存。匿名来源 OE-9944、OE-CAE6。

<a id="e02"></a>

## E02 公出里程、行程汇总和发票各承担什么作用

一次自驾公出报销中，用户已有里程统计表，提供实际票据，并特别追问通行费行程汇总单与发票是否采用同一处理路径。这个问题涉及两个层次：文档能读出哪些内容，以及哪些内容可以作为费用依据。应先核对车程、里程核算与票据对应的项目，避免把同一支出在汇总单和票据中累计两次。该案例的里程费率只适用于原任务，没有在此重新核验原票。匿名来源 OE-00E8。

<a id="e03"></a>

## E03 把一个已做过的报销类型交给其他同事

用户报告一种报销类型的技能和操作手册已经建好，随后询问如何让同事为其他单据类型继续开发。另一次复盘追问，如何把探索得到的业务知识留给接手者，避免从零重复验证。整理时应保留单据类型、资料对应关系和真实界面已观察到的行为，新增类型重新核验其字段与草稿状态。来源能确认用户提出了复用和交接需求，原系统的验收结果需回本次授权的系统或产物核对。匿名来源 OE-58CF、OE-CB56。

<a id="e04"></a>

## E04 现场审核时，历史模板里的物品选不出来

用户要求依照模板新建报销单，填写后留在页面现场审核，明确要求保持未保存。助手报告按编码、名称和清空筛选分别查询，当前物品选择框均为空，相关行仍未填妥。历史模板证明过去曾选过，在此次账号、表单和查询条件下仍须找到可选择的真实档案。原因当时没有查实。把缺失行和查询范围交给审核人，再根据本次授权决定下一步。
