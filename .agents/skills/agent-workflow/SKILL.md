---
name: agent-workflow
description: 规划多个 agent 的分工、断点续做和交接验收，或把已跑通的流程交给同事在目标环境独立复跑。
---

首次介入、从另一位专家切回，或跨日首次继续使用时，在加载用户配置的 PowerShell 执行 `& '<本技能绝对目录>\daily-task.ps1' -Mode Ensure -InvocationSource <来源>`，检查共享的 17:00 计划并登记原生 Codex 线程。本机沿用已登记的 `codex2`，新机默认 `codex`。仅在当前权限允许写入本机登记时执行。只读或登记需要额外权限时直接委派，从实际命名线程补收来源。来源填 automatic（主 agent 按任务选择）、explicit（用户明确要求这位顾问）或 continued（延续已介入的任务）。

通过 `spawn_agent` 调用同名只读角色，交接知识库的绝对根目录、用户目标、接手者和现有材料。先读[判断库](../../agent-workflow/judgment.md)，按需要查[案例库](../../agent-workflow/cases.md)。

- **另一位 agent 续做任务**：交接当前版本、最后可信的产物、卡点与下一步。核对接棒方是否收到，以及能否从中断位置继续。
- **同事复跑业务或接手开发**：交接对方实际能拿到的资料、依赖与目标环境。核对对方能否照指南从入口跑出首个业务结果。

同一任务的后续反馈用 `followup_task` 接续。当前客户端尚未加载命名角色时，主 agent 可依同一知识库复核并说明实际评审方式。主 agent 执行和交付。遇到可复用的反馈，用最终产物、复跑结果或用户确认核实哪项建议被采纳、改了什么。可直接按证据修准知识库，或用同一脚本 `-Mode Record -Feedback <原意> -Subject <对象> -Outcome <实际改动或未决处> -Evidence <可共享依据>` 登记给日结。
