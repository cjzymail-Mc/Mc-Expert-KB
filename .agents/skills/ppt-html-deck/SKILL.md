name: ppt-html-deck
description: 用户点名 PPT 与 HTML 汇报顾问时使用。让同一位专家跟进底稿、证据和改稿取舍，复核最终版式与可编辑性，也支持单次咨询。
---

主 agent 负责调度与落稿。用户点名后，沿用本任务已有的专家线程，或用 `spawn_agent` 的角色选择参数启动 `ppt-html-deck`。默认 `fork_turns="all"`。用户明确要求盲测时，新开线程并设 `fork_turns="none"`，只交接允许的材料。若当前工具无法选择该命名角色，主 agent 可依据同份判断库完成复核，交付时说明实际评审者。

首次交接给出本技能所在知识库的绝对路径。按仓库布局，[角色配置](../../../.codex/agents/ppt-html-deck.toml)、[判断库](../../ppt-html-deck/judgment.md)和[案例库](../../ppt-html-deck/cases.md)属于同一套文件。同时交代这轮要交什么，以及用户最后指定的底稿或已确认的 HTML 在哪里。涉及多个附件时，点明哪个决定版式、哪个提供数据、哪些批注来自用户。

一次点名默认覆盖本次任务。把后续纠正、受影响的页或对象和新版本送回同一线程，用 `followup_task` 接续已返回的专家。用户限定只问一句或只审某页时，按该范围处理。交付格式跟着当前要求走。已约定先审 HTML，就把可打开的 HTML 作为本轮交付。直接要独立补充章时，交 PPT 和主稿的建议插入位置。

交付前送审实际候选稿。已审 HTML 转可编辑 PPT 时，一并交已审 HTML、最终 PPT 的逐页渲染，以及制作方在副本中改字、移图或换图并保存重开的结果。约定可改数据的图表也附试改结果。本地 HTML 则说明从交付位置打开后，图片、翻页和本次涉及的链接是否可用。由专家对照本次目标判断，制作方修正后再送回受影响部分。缺少候选文件或实测时，说明已核查的范围。

有新的用户纠偏时，主 agent 在现有权限内维护同一知识库。先核对原话、适用范围和最新条目。用户明确要求以后沿用的判断写入 `judgment.md`，某次取舍的经过写入 `cases.md`。共享案例使用概括后的材料，内部实测数据、原始会话定位及本机文件路径留在有权限的本地资料中。已有条目优先修准，避免重复计入同一反馈。写入后核对引用，再用一句话说明记住了什么。
