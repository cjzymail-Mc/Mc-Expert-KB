description: 制作或修改面向听众的 PPT、HTML 汇报时，判断叙事、证据、改稿范围和可编辑性，并跟进候选稿。
---

主 agent 负责调度与落稿。需要本专家判断时，沿用本任务已有的专家线程，或用 `spawn_agent` 的角色选择参数启动 `ppt-html-deck`。默认 `fork_turns="all"`。用户明确要求盲测时，新开线程并设 `fork_turns="none"`，只交接允许的材料。若当前工具无法选择该命名角色，主 agent 可依据同份判断库完成复核，交付时说明实际评审者。

Windows 上首次介入、从其他专家切回或跨日首次继续时，主 agent 在当前项目目录用已加载用户配置的 PowerShell 执行 `& '<本技能绝对目录>\daily-task.ps1' -Mode Ensure -InvocationSource <来源>`。脚本检查所有专家共享的 Windows 计划，并登记本次专家和线程，首次按本机已指定的入口注册；新电脑未指定时用 `codex`，用户指定时传 `-Launcher codex2` 或 `-Launcher codex`。成功后才保存本机登记。计划时间为本地每天 17:00，使用当前已登录的 Windows 用户。仅在当前权限允许写入本机登记时执行。只读或登记需要额外权限时直接委派，从实际命名线程补收来源。来源填 automatic（主 agent 按任务选择）、explicit（用户明确要求这位顾问）或 continued（延续已介入的任务）。

对本次汇报任务，已当场入库的照常交付。有值得复盘但尚未入库的纠偏，主 agent 在当前项目目录用同一脚本 `-Mode Record -Feedback <用户原意> -Subject <页或对象> -Outcome <实际取舍或待核实处> [-Evidence <可共享的证据摘要>]` 留下反馈；共享字段只写经概括的材料。后续补充沿用同一对象并说明证据变化。每日复盘合并待处理反馈与已调用线程的相关增量。有直接命名角色调用时也能定位；无新经验即可结案。失败下次补跑。有跨工作区的写入限制时按当前权限请求写入或说明尚未登记。

首次交接给出本技能所在知识库的绝对路径。按仓库布局，[角色配置](../../../.codex/agents/ppt-html-deck.toml)、[判断库](../../ppt-html-deck/judgment.md)和[案例库](../../ppt-html-deck/cases.md)属于同一套文件。同时交代这轮要交什么，以及用户最后指定的底稿或已确认的 HTML 在哪里。涉及多个附件时，点明哪个决定版式、哪个提供数据、哪些批注来自用户。

首次介入默认跟进本次汇报任务。把后续纠正、受影响的页或对象和新版本送回同一线程，用 `followup_task` 接续已返回的专家。用户限定只问一句或只审某页时，按该范围处理。交付格式跟着当前要求走。已约定先审 HTML，就把可打开的 HTML 作为本轮交付。直接要独立补充章时，交 PPT 和主稿的建议插入位置。

交付前送审实际候选稿。已审 HTML 转可编辑 PPT 时，一并交已审 HTML、最终 PPT 的逐页渲染，以及制作方在副本中改字、移图或换图并保存重开的结果。约定可改数据的图表也附试改结果。本地 HTML 则说明从交付位置打开后，图片、翻页和本次涉及的链接是否可用。由专家对照本次目标判断，制作方修正后再送回受影响部分。缺少候选文件或实测时，说明已核查的范围。

用户纠正方向或要求复盘近期案例时，主 agent 在现有权限内维护同一知识库。对照用户原话、实际成稿和已有条目，分清用户提出的要求与顾问在成稿中发现的问题。用户明确要求以后沿用的判断写入 `judgment.md` 的「已明确的要求」。有复用价值的做法写清适用条件，放到同文件的场景判断中，在 `cases.md` 记录促成这次取舍的证据。共享案例使用概括后的材料，内部实测数据、原始会话定位及本机文件路径留在有权限的本地资料中。已有条目优先修准，避免重复计入同一反馈。写入后核对引用，再用一句话说明记住了什么。
